# Cinematic Premium 1.3 — implementation and review

This release enhances the existing Android app. The audit and incremental roadmap are in [CINEMATIC_REDESIGN.md](CINEMATIC_REDESIGN.md). No accounts, subscription media, API keys, or production catalog fixtures were added.

## Shared system

`DesignSystem.kt` centralizes #080B12 background, #151B28 surface, #242D3E elevation, #7C3AED primary action fill, #38BDF8 highlight, #F8FAFC content, #A1A1AA secondary text, #EF4444 live marker, and #22C55E success tokens. Small purple action text uses #C4B5FD. This foreground distinction matters: saturated purple has only 3.02:1 contrast on the surface, whereas the text variant has 9.33:1. Primary text has 16.46:1 and secondary text 6.72:1 on the surface. White on the primary button is 5.70:1. Live labels use a lighter foreground plus the word LIVE. These are computed sRGB ratios, not measurements of arbitrary artwork pixels.

Roboto/system sans-serif typography defines display, hero/headline, rail/title, card, body, metadata and button roles. TV mode increases the scale. The system font scale is multiplied by the user's existing text preference; it is never clamped to 1. Native button minimum height is 48dp; Compose actions use the same minimum. Spacing follows 4/8/12/16/24/32dp, posters/buttons use 12dp corners, and dialogs use 24dp. Optional focus scaling is 1.025× over 140ms and affects drawing rather than layout. The existing motion preference and Android animator setting gate it. Light mode and high-contrast settings remain available.

`CinemaTextButton` and the outlined `Action` use the accessible foreground color; filled actions retain saturated purple. `CinemaIcons` distinguishes broadcast TV, film and series navigation without another dependency. `LoadingSkeleton`, `ErrorState`, `PlaybackProgress`, `CategoryFilter`, `ChannelListItem`, `PosterRail`, `FeaturedHero`, `PremiumCard` and the existing VOD/episode components share the system.

## Ownership and concurrency

Preview creates one Media3 engine only after explicit start. Focus movement never creates engines. The existing engine replaces the selected media item. `LifecycleStartEffect` releases the preview when stopped or removed. Fullscreen releases it before starting `PlayerActivity`; engine release is idempotent. No new background playback service or second account connection was introduced.

Guide focus requests debounce for 200ms, cancel their predecessor and retain at most 24 cached schedules. Optional hero metadata uses the existing bounded details cache. VOD continues to use the existing indexed account cache and paged browser. Network endpoints, credentials, provider URLs and on-demand queue contracts remain compatible. Invalid EPG intervals are rejected; no negative-duration cells are rendered.

## Localization and accessibility

English and Arabic resources cover navigation, provider connection forms, main actions, core feedback, live browsing, EPG, seasons/episodes, catalog browsing, native player action labels and common settings/error messages. Android 13+ locale configuration advertises both languages; older devices follow the system locale. `UiLabels.kt` resolves legacy enum/query/preference presentation labels without changing persisted preference keys or provider content. Provider artwork, names and descriptions retain their supplied language. Episode labels isolate mixed-direction provider names. Arabic count resources include zero/one/two/few/many/other forms.

The large-text test renders the real login composable at 1.8× system font scale in an Arabic RTL context and verifies that the connection action remains reachable. This is a targeted layout check, not a full TalkBack or every-screen translation certification. Some legacy diagnostic/provider metadata strings can still be English; native speaker review and a complete runtime localization/accessibility pass remain advisable. Text in imagery remains on deliberate dark scrims even when light mode is selected.

## Intentional capability limits

This provider integration exposes `get_short_epg` for up to eight programmes. The UI therefore does not pretend to provide a synchronized multi-channel full-day guide, archived date browsing, catch-up, reminders, or program search over an unavailable archive. Each timeline is the selected channel's actual short schedule. Other channel rows do not fabricate current program titles. Displayed channel numbers are local catalog ordinals, not a claimed provider LCN mapping.

There is one account and no pre-existing profiles, so no decorative profile selector was added. M3U/XMLTV imports, multiple accounts, casting, recording and downloads remain separate scope. Popularity, stream quality badges, skip-intro and skip-credits need trustworthy metadata and are not invented. Local recommendations remain the existing deterministic category/genre approach.

The deliverable is a debug-signed testing build. No production-readiness, startup, frame-rate, physical-remote or low-memory-device certification is implied. See [CINEMATIC_VALIDATION.md](CINEMATIC_VALIDATION.md) for the actual checks and artifacts.
